# ZasDict for Windows

イジェール語用ローカル辞書ソフト ZasDict の Windows 版。C# / .NET 8 / WPF 製。
OBS で画面を配信しながら編集することを前提に、ダイアログとポップアップの構成を組み直しています。

## OBS 前提の設計

OBS の［ウィンドウキャプチャ］は対象ウィンドウの HWND だけを取り込むため、別ウィンドウとして
生成される UI 要素は配信に映りません。本アプリはそれを避けるため次の構成を取っています。

- `MessageBox` / `ContextMenu` / `ComboBox` のドロップダウンを使わない。
  確認・警告・単語ごとの操作メニューはすべてメインウィンドウ内のオーバーレイ層に描画する
- `ToolTip` も別 HWND なので配信には映らない。補助説明にだけ使い、それが唯一の手掛かりになる情報は
  必ず画面上の文字でも示す（例: 未保存はヘッダのドットに加えてタイトルバーの `*` でも分かるようにする）
- 検索モード、検索対象の選択は chip 型トグル（`Theme.xaml` の `Chip` スタイル）
- プルダウンは `DropDown.cs` の自前コントロール。一覧を `Popup` ではなくウィンドウ最上段の
  `AdornerDecorator` に描くため配信に映る。`IsEditable` を立てると本体が入力欄になり、
  一覧に無い値も打てる（単語エディタの関係名）
- 本体は左に検索と一覧、右に単語詳細の 2 面。右はタブ束で、単語詳細はその据え置きの 1 枚目
  （閉じられず、他所へも運べない）
- オーバーレイ（単語エディタ、例文エディタ、例文一覧、ツール、凡例・統計、設定）は上下左右の縁か
  中央（＝単語詳細と同じ枠）に付き、何枚でも同時に開ける。浮かせるモーダル表示は確認ダイアログ専用
  - 同じ場所に寄せたものはタブになり、タブで切り替える。別々の場所に分ければ同時に見える
  - タブの見出しを掴んで別の場所へ運べる。ドラッグを始めると縁の 4 つと中央の計 5 つの候補が出て、
    離した升目に移る。取りやめは Esc。行き先は種類ごとに、大きさは辺ごとに `settings.json` に残るので、
    配信のレイアウトを毎回組み直さずに済む
  - ドロップ先の候補は縁の細い帯と、その内側の中央。帯の太さは窓の大きさによらず一定で、ヘッダ・フッタと
    ブラウザサイドバーを避けて描くので、候補と実際に収まる範囲が一致する
  - スクリムを敷かないので、開いたまま検索・一覧・詳細を操作できる。配信で辞書を映したまま書き足す用途を
    想定している。ブラウザサイドバーも出したままにできる（場所を取り合わないため）。
    中央に寄せたものだけは単語詳細と入れ替わりで表に出るので、詳細に戻すにはタブを選び直す
  - 同じ種類は 1 枚まで。開いている種類のボタンとショートカット（＋単語 / 編集 / 複製 / 削除、例文、ツール、
    凡例・統計、設定）は無効になる。書きかけの入力が差し替えで消えるのを防ぐため。
    単語エディタか例文エディタを開いている間は［開く］［新規辞書］も止める（保存の宛先だけが
    別の辞書に入れ替わるのを防ぐため）
  - 辺の大きさは窓の 35% までに抑える。`DockPanel` は最後の子（＝検索と詳細）に「残り」しか渡さないので、
    上限が無いと 4 辺に広げたときに本体が 0 幅まで潰れて操作できなくなる。それでもサイドバーを大きく
    開いたまま左右へ寄せると本体は細くなるので、そのときはサイドバーを閉じる
  - 確認ダイアログだけは辺に付かず、開いている画面の上に中央のモーダルとして重ねる
- **単語ウィンドウ**（ヘッダの［単語ウィンドウ］）は独立した HWND。選択中の単語だけを大きく表示する。
  背景色・文字サイズ倍率・訳語や内容の表示可否を設定できる
- **ブラウザサイドバー**（ヘッダの［ブラウザ］）は WebView2 をメインウィンドウに埋め込む。子 HWND なので
  ウィンドウキャプチャにページがそのまま映る。ただし WebView2 は WPF より手前に描画される（airspace の
  問題）ため、窓全体を覆う確認ダイアログを開いている間は自動的に隠れる。
  辺に付いたオーバーレイとは並ぶだけなので、そのときは隠さない

例外はファイルダイアログ（開く／保存／フォント選択）です。OS のウィンドウなので配信には映りません。

### OBS 側の設定

1. ソースに［ウィンドウキャプチャ］を追加し、`ZasDict for Windows` を選ぶ
2. 単語だけを別枠で見せる場合は、もう 1 つ［ウィンドウキャプチャ］を追加して `ZasDict 単語ウィンドウ` を選ぶ
3. 単語ウィンドウを切り抜くなら、設定 → 単語ウィンドウ で背景色を `#00B140` にし、OBS 側でクロマキーフィルタを掛ける

### テーマの制約

配色とコントロールの外見は `Theme.xaml` に集約している。キー名を変えると呼び出し側（オーバーレイ類）まで壊れるため、調整は値の変更でおこなう。

- 影・ぼかし（`DropShadowEffect` などの `Effect`）は使わない。ビットマップ化されて文字がにじみ、OBS のウィンドウキャプチャで画質が落ちるため、奥行きは面の明暗と枠線だけで表現する
- アクセントカラーは `#A78BFA`。hover / pressed は背景を塗り替えず白・黒のヴェールを重ねる方式にして、Primary などのグラデーションを潰さない
- 角の丸みは要素の大きさで 3 段。カード `12` / ボタン・入力欄 `8` / chip・タグ・バッジ `6`。長丸（`CornerRadius="999"`）は使わない。文字数の少ない chip やタグがほぼ真円になり、隣り合う角丸の部品と形が揃わないため
- ヘッダは幅 1280px で 1 行に収まるコンパクト設計。ボタン文言にはコードビハインドから文字列を代入するもの（単語ウィンドウなど）があるので `Content` はプレーンテキストのままにする
- 入力欄の案内文字は `v:Placeholder.Text` 添付プロパティ。TextBox テンプレートが「空のときだけ」表示し、入力値そのものには触れない
- `StreamWindow.xaml`（単語ウィンドウ）は意図的にテーマ適用外。背景色がクロマキー用の固定値になるため、配色の差し替えを波及させない
- `TabItem` のカスタムテンプレートでは、ヘッダー用 `ContentPresenter` に `ContentSource="Header"` を必ず付ける。省略すると `TabItem.Content`（ページ本体）がヘッダー枠の中に描かれ、TabPanel が子を無限サイズで測るため内側の ScrollViewer に高さが渡らずスクロール不能になる。加えて FlowDocument が無限幅で Arrange され、WPF 内部の PtsHost が FailFast（try/catch 不能）でプロセスを落とす
- オーバーレイ類の ScrollViewer は `HorizontalScrollBarVisibility="Disabled"` に統一する。横方向のはみ出しは折り返しと末尾省略で吸収させ、横スクロールで行順が入れ替わる状態を作らない
- 既定（暗黙）の TextBlock スタイルは明示的な `Style` 指定で打ち消される。`Label` / `SectionHeading` などキースタイル側で `TextWrapping="Wrap"` を宣言し直さないと、長い案内文が幅を超えて末尾が切れる
- 逆に `TextTrimming="CharacterEllipsis"` は `TextWrapping="NoWrap"` とセットで書く。既定スタイルも `Label` も `Wrap` なので、`NoWrap` を書かないと折り返しが優先されて省略記号が一生出ない。1 行に収めたい欄（見出し語の一覧、フッタのステータス、パス表示、入力欄の案内文字）は両方を明示する

## 例文

辞書ルート直下の `examples` 配列を扱う。ZasDict（Python 版）が書く形と同じで、相互に読み書きできる。

```json
{ "id": 4, "sentence": "Bei renkeu reeke n …", "translation": "りんごが好きな子供は…",
  "supplement": "", "tags": [], "words": [{ "id": 579 }],
  "offer": { "catalog": "zpdicDaily", "number": 4 } }
```

- 例文が 1 つも無い辞書には `examples` キー自体を書かない。他ツールとの差分をむだに増やさないため
- `words` には id だけ書く。見出し語は辞書側が正で、表示のたびに引き直す。指している単語を消した場合は
  `id:12` と出るので、例文を直すかどうかは書き手が決められる（例文の側から参照を自動で外すことはしない）
- 出典（`offer`）はプルダウン（`DropDown.cs`）で選ぶ。保存するのは API 名だけで、一覧の表示名は
  `Const.ExampleCatalogs` の `Label`
- 「自作」以外の出典は ZpDIC Online の `exampleOffer` API に番号で照会でき、訳と補足を引ける。
  APIキーは `%APPDATA%\ZasDictWin\zpdic_api_key` に置く。`settings.json` は辞書のパスと表示設定だけを
  持つ約束なので、秘密情報はそちらに混ぜない
- 「自作」を選んだ例文の `offer.number` には例文自身の id を入れる（ZasDict と同じ）

## 選択肢のカスタマイズ

編集画面のプルダウンに並ぶ語彙は `%APPDATA%\ZasDictWin\choices.json` にまとまっている。初回起動時に
既定値で書き出されるので、辞書に合わせて書き換えればビルドし直さずに反映される（反映は次回起動から）。
既定値は `Choices.cs` のプロパティ初期値で、ZasDict（Android 版）の `Const.kt` と同じ並び。

| キー | 中身 |
| --- | --- |
| `Pos` | 品詞。訳語ごとに 1 つ選ぶ（保存時の必須項目） |
| `ContentTypes` | 内容欄の種類。書いた順に追加ボタンが並び、各項目は 1 つまで |
| `Relations` | 関係名と対照になる関係名。設定 → 表示・動作 からも編集できる |
| `ExampleCatalogs` | 例文の出典。`Api` が ZpDIC Online に渡す名前、`Label` が表示名 |

- 空の配列・空のオブジェクトを書いた項目は既定値に戻す。選択肢が 1 つも無いと選べなくなるため
- 出典から「自作」を消しても戻す。ZpDIC に照会しない例文の受け皿がなくなるため
- `発音記号`・`語源`・`自作` は処理に結び付いた値で、実体は `Const.cs` にある（`発音記号` は
  「特殊発音」タグの自動付与、`語源` はイジェール文字での描画）。選択肢から外すとその自動処理だけが
  働かなくなる
- `settings.json` とは分けている。あちらは辞書のパスと表示設定だけを持つ約束のため

## 障害ログ

キャッチできた例外は `%APPDATA%\ZasDictWin\error.log` にスタックトレースを追記し、アプリは落とさずにオーバーレイで案内する（MessageBox は別 HWND なので OBS に映らない）。画面に出す先が無い失敗（設定の読み書き、Heksa フォントの読み込み、`ignoredPattern` の解釈）も、黙って既定値に戻る理由が後から追えるよう記録だけは残す。レポート時にはこのファイルを添付する。Markdown 描画が原因の PtsHost FailFast はキャッチ不能なため、ログには残らずプロセスが終了する。

## ビルド

.NET 8 SDK が必要です。

```
dotnet build ZasDictWin.sln -c Release
dotnet run --project ZasDictWin.csproj
```

Visual Studio 2022 なら `ZasDictWin.sln` を開いて実行。

ブラウザサイドバーのために `Microsoft.Web.WebView2` NuGet パッケージを 1 つだけ使用します
（初回ビルドで復元され、`bin` に DLL と `WebView2Loader.dll` が出力されます）。実行には
WebView2 ランタイムが必要で、Windows 10 以降なら Microsoft Edge に同梱されていることがほとんどです。
無い場合は [Evergreen ランタイム](https://developer.microsoft.com/microsoft-edge/webview2/) を導入してください。
ランタイムが無い環境でもアプリ自体は起動し、サイドバーにエラー表示が出ます（ブラウザ用の
ユーザーデータは `%APPDATA%\ZasDictWin\WebView2` に作ります）。

| 検索モード | 前方 / 部分 / 後方 / 完全 |

| 単語の追加 / 編集 / 複製 / 削除 | FAB 相当の［＋ 単語］、一覧の「⋯」、詳細画面のボタン。追加時は検索欄の文字列が見出し語の初期値になる |
| 単語エディタの項目 | 見出し語 / タグ / 訳語（品詞はプルダウンで選択）/ 内容（語法・文化・用例・語源）/ 関連語（関係名はプルダウン。一覧に無い名前は直接入力できる）/ 変化形 |
| 訳語の表示区切り | 同じ品詞の複数の訳語はカンマ区切り（`犬, 狗`）。検索一覧・詳細・単語ウィンドウで共通。品詞見出しは `［名詞］犬, 狗` を 2 つのスペースで並べる |
| 関係の対照登録 | 追加・削除とも相手側に自動反映。見出し語の変更は参照側の form にも波及。削除時は被参照を除去 |

| IPA → 綴り | `Services/Ipa.cs` |
| 凡例・統計 | 辞書内の `legend`（無ければ `zpdicOnline`）の表示と、語数・訳語数・関係数・品詞内訳・タグ内訳 |
| 辞書依存設定 | `punctuations` と `ignoredPattern`。辞書の `zpdicOnline` に書き戻す |
| 環境設定 | 文字サイズ倍率、自動上書き保存、Heksa フォント、字順、関係の対照表 |
| オーバーレイの配置 | 上下左右の縁と中央（単語詳細と同じ枠）にタブで並べる。何枚でも同時に開け（同じ種類は 1 枚まで）、非モーダルなので本体をそのまま操作できる。タブを掴んで別の場所へ運べ、行き先と大きさは `settings.json` に記憶する（上の「OBS 前提の設計」を参照） |
| ブラウザサイドバー | ヘッダの［ブラウザ］で開閉し、右に WebView2 を表示。アドレス欄で Enter で移動、URL でない語句は Google 検索に回す。戻る／進む／再読み込み、幅のドラッグ調整と記憶に対応。下部のステータス欄は 1 行固定で、長い URL は末尾を切るのではなく途中を `…` で省略して先頭と末尾を見せる（`EllipsisMiddle`）。開始 URL と起動時に開く可否は設定の「ブラウザ」タブ |
| Heksa の適用範囲 | 検索欄・一覧の見出し語・詳細の見出し語／変化形／関連語・単語エディタの綴り欄・単語ウィンドウの見出し語・詳細と単語ウィンドウの語源欄（イジェール語の語幹だけ。下の「語源欄の描き分け」を参照） |
| 未保存の表示 | タイトルバーとヘッダに `*` |

### 語源欄の描き分け

語源欄は辞書の凡例が定める `{造語者/言語略称:単語|意味}` 記法で書かれている（実データに波括弧は無い）。
`Etymology.Split` がこれを解析し、イジェール語の語幹だけを Heksa で描く。判定は次のとおり。

| 書き方 | 描き分け |
| --- | --- |
| `dos+icen` | 言語略称が無いので両方イジェール文字 |
| `cal/mo+aker` | `cal/`（造語者＝かりぐら）はラテン文字、`mo`・`aker` はイジェール文字 |
| `*nes+for\|足の重ねる所` | `*`（廃用語）と `\|` 以降の和訳はそのまま、語幹だけイジェール文字 |
| `ru:Кобальт` | 外来語源。`ru`・`a`・`r`・`en`・`de`・`zh`・`u` などはイジェール文字にしない |
| `i.a:kel` | `i` で始まる略称（i / i.a / i.s / i.k / i.t、実データにある i.r・i.o も）はイジェール語 |
| `a:>i.t:` | `+`（合成）と `>`（変化）が区間の区切り |

区間の種別だけでなく文字種でも絞っており、イジェール文字にするのは `A-Z a-z ' -` が連続する範囲のみ。
語源欄に和訳や引用文が紛れ込んでいる語があるため、仮名やキリル文字を巻き込まないようにしている。

## 移植上の注意

- `dialects.py` の `titauini()` は 3母音化の結果が次の行で破棄されます。既定では同じ挙動を保ち、
  ツール画面のチェックボックス（`Dialects.FaithfulTitauini`）で 3母音化を有効にできます
- `ignoredPattern` は前方・後方・完全一致でのみ見出し語から除去します。部分一致に適用すると
  入力した記号が永久にヒットしなくなるためです
- 関係の対照表（例: `上位語=下位語`）の既定値は ZasDictAndroid の `Const.RECIPROCAL_MAP` と同じです。
  `choices.json` に保存済みの対照表は既定値より優先されるため、古い設定を引き継いでいる場合は
  設定 → 表示・動作 の［既定に戻す］で入れ直してください
- 設定は `%APPDATA%\ZasDictWin\settings.json` に保存されます。辞書のパスと表示設定のみで、
  秘密情報は含みません
- Heksa フォント（`Fazik-regular.ttf`）はリポジトリに含めません。設定 → 表示・動作 から取り込みます
